# Contributing to ThreatLens

Thanks for helping improve ThreatLens. This project is built for self-hosted security teams, so changes should stay practical, well-tested, and deployment-friendly.

## Before You Open a PR

- Search existing issues and pull requests before starting work.
- Keep changes focused and easy to review.
- Update docs when behavior, configuration, or operator flow changes.

## Development Expectations

- Prefer small, incremental commits.
- Run the relevant tests for the area you touched.
- Add or update tests for bug fixes and behavior changes.
- Keep security-sensitive changes explicit and easy to audit.

## Pull Requests

- Describe the user impact and deployment impact.
- Call out config changes, migrations, and operational follow-ups.
- Include screenshots or request/response examples when they help explain the change.

## Reporting Problems

- For general bugs, open an issue with clear reproduction steps.
- For security issues, follow `SECURITY.md` and avoid public disclosure until the issue is reviewed.
