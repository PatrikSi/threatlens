# Read-only MCP implementation review

Date: 2026-09-17

## Scope

The optional MCP endpoint exposes five bounded tools over stored ThreatLens
records: article search, article evidence, team assessments, investigations, and
reports. It defaults to disabled. Retrieval does not invoke AI providers, fetch
external URLs, queue processing, mutate domain records, or execute hunt cards.
Credential-use timestamps and redacted access audits remain operational writes.

The first connection mode uses explicitly scoped ThreatLens personal API tokens
or service-account credentials. It is not an OAuth authorization server and
does not support OAuth-only clients. Current service-account permissions permit
the two article tools; personal tokens can expose additional tools according to
the user's current permissions and record access.

## Reviewed boundaries

| Area | Enforced behavior |
| --- | --- |
| Credentials | Every request requires a current bearer credential with literal `read:mcp` opt-in and ordinary feature permissions. Browser sessions, provider keys, legacy broad scopes, and URI credentials do not grant MCP access. |
| Record access | Shared authorization, handling-label, team-membership, ownership, and derived-source egress checks apply. Discovery is filtered by the principal's effective permissions. |
| Publication | A continuous read transaction retains permission locks through the outer ASGI response transfer. Credential/assertion expiry shortens the transfer deadline; a lost transaction cannot silently reopen the fence. |
| Connection capacity | Two connections are acquired before authorization locks and pinned across credential-use and audit commits. Admission is capped by configured concurrency and half the process pool capacity. |
| Auditing | A separate transaction records operation and outcome without source text, search terms, guessed resource IDs, or bearer secrets. Immutable actor metadata avoids implicit ORM reads after rollback. A prepared audit does not claim confirmed delivery. |
| Protocol | Current `2026-07-28` and legacy `2025-11-25` flows are stateless. Header/body agreement, closed request schemas, numeric limits, Unicode validity, nesting, and message byte limits are checked. |
| Capacity | SQL projections bound article/report text and saved JSON materialization. Lineage checks have an explicit size ceiling. Redis admission fails closed and applies source/principal budgets across API processes. |
| Result quality | Responses disclose provenance, freshness, canonical links, and truncation. Structured extraction stays an atomic unit when omitted for size. Hunt-card review status must be inspected; a stored hypothesis is not a confirmed finding. |
| Pagination | Article cursors bind filters, principal, credential, policy revisions, and a 30-minute search window. Byte-budget truncation preserves the continuation position. |
| Browser access | An independent exact-origin allowlist controls browser requests. Cookie authentication, wildcard origins, compressed request bodies, and query parameters are rejected. Responses are not cacheable. |
| Compatibility | No database migration or production MCP SDK dependency is added. The existing REST interfaces retain their authentication and error contracts. Bootstrap and Compose expose the new configuration defaults. |

Independent reviews covered the authorization lifecycle, protocol and client
compatibility, retrieval boundaries, deployment instructions, and failure paths.
Final review additionally checked audit-operation allowlisting and the existing
service-account permission restrictions.

## Qualification

The first full backend run exposed a dependency-layer violation, missing route
permission metadata, and logging-context leakage in direct authentication tests.
HTTP authentication composition now lives in `app/api/mcp_context.py`; services
retain the authorization fences. The route advertises its enforced scope using
the existing permission metadata, and direct-auth tests restore their logging
context. No architecture or permission checks were exempted.

The clean full backend rerun passed **3,636 tests**, with five expected skips,
in 15 minutes 16 seconds. The skipped checks are the two opt-in capacity/recovery
harnesses and optional SDK tests, with the SDK checks exercised separately.
Combined line/branch coverage is **86.37%**, and reporting coverage is **86.66%**.
`scripts/check_coverage.py` passed every existing threshold and all nine new MCP
module thresholds without lowering any existing minimum. MCP runtime coverage
is 100%; the API composition, access, protocol, and transport modules exceed 90%.

Both supported protocol revisions passed against official Python SDK 2.2.0.
The final ordered integration run passed all 66 cases, including every new MCP
integration module, actual SDK requests through FastAPI/PostgreSQL/Redis, and
the subsequent Celery/logging tests that previously detected context leakage.
It also verifies that SDK clients receive useful tool-error content rather than
mistaking an error for a successful structured result.

The [disposable proxy smoke](../../scripts/verify_mcp_proxy.py) passed with actual
nginx and Uvicorn, migrated synthetic PostgreSQL data, and Redis. It covered
current discovery and legacy initialization, scoped tool discovery, search and
article evidence, Authorization/MCP header forwarding, Origin checks, both SDK
modes, the credential-use commit, and revocation on a later request. The smoke
used existing local dependency images with current source/configuration mounts,
not newly built release images. All disposable containers and networks were
removed; the running application and its data were unchanged.

Focused regressions additionally cover audit-write failure withholding data and
releasing both connections, read-fence loss, expiry, bounded output, cursor
continuation after truncation, and slow/disconnected clients at the ASGI boundary.
The service-account HTTP test uses all currently supported read permissions and
still exposes exactly the two article tools. Unknown client-supplied tool names
are not retained as audit operation names.

Bootstrap/Compose/Kubernetes environment tests passed all 23 cases. Backend
Ruff, the source-size gate for 832 production files, generated API-contract checks,
and whitespace checks passed. The CI coverage gate now includes the MCP API
composition, route, authentication, dispatch, protocol, retrieval, runtime, and
transport modules. The SDK dependency remains isolated from production runtime
requirements.

## Limits and follow-up work

- OAuth authorization and hosted-client qualification remain separate work.
  Use a client supporting a custom Authorization header for this release.
- The request deadline bounds SQL work and response output/transfer. Initial
  shared-pool checkout, connection establishment, and cleanup can add elapsed
  time under their ordinary database timeouts. No authorization locks are held
  during initial checkout. Pool admission does not reserve capacity from other
  API traffic.
- The tools return bounded excerpts. Reports and investigations currently use
  collection limits with canonical links rather than continuation cursors.
- Search matches stored titles and summaries. Semantic retrieval, MCP prompts,
  subscriptions, asynchronous tasks, and mutations are not part of this scope.
- ThreatLens cannot recall data already copied to an external client or its
  model provider. Retrieved source content remains untrusted evidence.
- Dedicated MCP latency, admission, and transfer metrics would improve capacity
  planning beyond the existing request logs and access audits. Synthetic
  qualification does not establish a production throughput target.
