# ThreatLens 2.1.1

This patch source candidate hardens authentication, retained analyst state,
background recovery and dependency packaging. It preserves the 2.1 API surface
and migration head `0125_webhook_article_text`. Image publication and hosted
release qualification remain pending.

The versioned OpenAPI contract SHA-256 is
`d124cb25ffeadb4073e7aa826abae7ec1c6d0fe16dac52ddd8eaccc45fc01490`.

## Main corrections

- New passwords reject line breaks that browser password fields discard;
  existing login/current-password admission remains compatible. OIDC discovery
  rechecks transport policy on redirects, and publisher previews safely handle
  normalized schemes and malformed links.
- Protected cached reads retire after access withdrawal. Late responses and
  mutations cannot restore an older permission generation. Analyst drafts remain
  available while saving pauses until the current read authority is verified.
- Repeated notification recovery publications require fresh consumer progress;
  publication releases require exact reservation ownership. AI worker outcomes
  remain durable, disabled feeds do
  not resume queued fetches, and metric-capture migration candidates are generated
  lazily.
- Runtime and test dependencies, frontend packages and native bases are updated.
  Backend images contain the application dependency set without pip or ensurepip.
  Resolve or install dependencies in the host development environment or rebuild
  the image. Host test requirements retain patched pip and pytest.

See the [2.1 feature overview](2.1.0.md#main-changes) for team intelligence,
reviewed publications, AI governance, automation and scoped MCP access.

## Upgrade

An existing 2.1.0 source installation already at migration `0125` requires no
additional schema migration. Installations upgrading from 2.0.x must
follow the [2.1 stopped-writer migration procedure](2.1.0.md#upgrade-from-20x),
including a verified backup, matching encryption key and separate database
identities. Upgrades from 1.x also require the
[2.0 compatibility procedure](2.0.0.md#upgrade-from-1x).

After matching 2.1.1 images are published and those prerequisites are satisfied:

```bash
export THREATLENS_IMAGE_TAG=2.1.1
docker compose pull
docker compose stop --timeout 300 api beat worker worker-ai worker-exports worker-maintenance worker-notifications
docker compose run --rm migrate
docker compose up -d --wait
docker compose ps
```

Use the same environment and Compose selection for every command. Do not mix
old and new API/worker processes. Verify readiness, login, ingestion, a synthetic
export and the intended access/notification settings after upgrading.

## Qualification and boundaries

The [November review](../reviews/2026-11-15-comprehensive-review.md) records full
tests and native-image checks for their original 2.1.0 source and image revisions.
Those historical receipts are not new 2.1.1 image or hosted-platform passes. The
version bump requires aligned metadata, regenerated API artifacts and focused
validation; its results are recorded separately.

Hosted browser, ARM64, native recovery and publication checks remain required,
along with the compatible committed-reference capacity comparison for
capacity-sensitive public-release changes. No new public tag, published digest,
production-topology or capacity clearance is claimed here. The existing
[2.1 product and browser boundaries](2.1.0.md#qualification-and-boundaries) and
[release process](../reference/release-process.md) still apply.
