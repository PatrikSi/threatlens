# ThreatLens 2.0.1

This patch fixes a web container startup regression for existing Compose and
Portainer deployments that pull newer images while retaining their stack
definition.

## Container compatibility fix

The original 2.0.0 web image runs as non-root `nginx` but retains the base
image's root-owned `/etc/nginx/conf.d/default.conf`. Without the newer Compose
configuration mount, the entrypoint cannot overwrite that file and exits with
`Permission denied`. The bundled writable tmpfs hid this defect in the initial
release checks.

The image now removes that inherited file during the build. At startup, the
shipped template creates a configuration owned by nginx. Existing deployments
with a writable container filesystem can start without adding mounts or
running the container as root. The bundled read-only setup continues to use its
bounded writable mounts.

Both architecture checks now exercise legacy writable-root and hardened
read-only startup, application HTTP responses, and container restart. The
publishing workflow applies these checks to the exact scanned image digests
before promoting them.

## Upgrade

For this web startup failure on an otherwise upgraded 2.0 installation, pull
the corrected web image and recreate the web service. A Compose edit is not
required for the original writable-root service definition. See the
[Compose and Portainer instructions](../pages/runtime-budgets.md#web-startup-permission-denied-after-an-upgrade).

Main-branch publication supplies the 2.0.1 build through `latest`, `main`, and
immutable commit image references. A version-shaped image tag is available
only if a corresponding public Git tag has also been released. Update an old
image pin deliberately; pulling an immutable pin does not change its contents.

This patch introduces no database migration or new required configuration.
Keep existing credentials, encryption keys and persistent volumes. Upgrading
from 1.x still requires the separate [2.0 upgrade procedure](2.0.0.md#upgrade-from-1x),
including the database-role cutover and coordinated worker changes.

Custom read-only filesystems or host-mounted nginx configuration still need
permissions and writable paths appropriate for the non-root image. The patch
does not change the permissions of host mounts.
